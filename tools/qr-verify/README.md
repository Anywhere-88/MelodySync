# QR 编码器验证工具

`ui/index.html` 里的二维码是**自研**的（离线应用不能依赖 CDN 的 qrcode.js），
所以必须证明它生成的码是符合 ISO/IEC 18004 的、能被真实扫码器识读的。

本目录就是那套验证手段，可以随时重跑。

## 为什么需要参考实现

二维码有几个环节「看起来能扫」但实际不合规（格式信息位、纠错分块交错、
掩码罚分），肉眼完全看不出来。所以这里用 Python 的 `qrcode` 库
作为**逐模块比对基准**。

## 准备

```bash
# 依赖（网络通畅时可省略，仅用于对照与解码校验）
pip install qrcode opencv-python-headless numpy
```

脚本里的 `NODE` 常量是 Node.js 的绝对路径，换机器时改一下。

## 运行

```bash
python make_verify_copy.py     # 生成带「强制掩码」开关的测试副本
python compare2.py             # ① 固定同一掩码，逐模块比对参考实现
python penalty_ref.py          # ② 用 Python 独立实现 ISO 罚分，交叉验证 JS
python mask_audit.py           # ③ 审计掩码优选是否取到 ISO 罚分最小值
python decode_ab2.py           # ④ 用 OpenCV 解码器把码扫回来
```

## 各项检查在验什么

| 脚本 | 验证目标 | 期望结果 |
|---|---|---|
| `compare2.py` | 纠错编码 / 分块交错 / 布点 / 格式与版本信息 | 同一掩码下**逐模块完全一致** |
| `penalty_ref.py` | JS 的罚分函数是否等于 ISO 18004 §8.8.2 | 每个掩码的罚分**逐值相等** |
| `mask_audit.py` | 最终选定的掩码是否为 ISO 罚分最小者 | **全部命中**最小值 |
| `decode_ab2.py` | 渲染成位图后能否被真实解码器读回 | 自研码的失败集合 ⊆ 参考库的失败集合 |

## 已知的两点说明

1. **掩码选择可能与 `qrcode` 库不同。** 这是正常的：`qrcode` 库的
   `lost_point` 实现与 ISO 规范有偏差，而本实现严格按规范来。
   两者都是合法二维码，扫码器都能读。`mask_audit.py` 用来证明
   我们选的是 ISO 意义上的最优掩码。

2. **`decode_ab2.py` 里会有一批「两者都失败」的用例。** 那是 OpenCV
   `QRCodeDetector` 对某些大版本 / 特定结构的位图本身识别不了，
   参考库生成的码同样解不出来。判断标准是看
   **「仅自研失败」是否为 0**，而不是看通过率。

## 历史上的坑（已修，留作参考）

- **时序图形与定位图形的绘制顺序**：必须先画时序（第 6 行/列），
  再画三个定位图形覆盖它的两端。反过来画会被时序冲掉定位图形的最外一行，
  整张码就废了。
- **`ECL_INDEX[x] || 1`**：纠错等级 L 的索引恰好是 `0`（falsy），
  用 `||` 兜底会把它变成 M。凡是索引可能是 0 的查表，都不能用 `||` 兜底。
